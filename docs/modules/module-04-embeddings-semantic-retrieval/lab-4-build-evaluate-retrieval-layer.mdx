<CourseCallout title="Lab framing">
  The goal is not to build the largest possible search stack. The goal is to make retrieval quality measurable: define a
  corpus, create relevance judgments, compare retrieval strategies, and explain which design choices are ready for a RAG
  or agent system.
</CourseCallout>

## Goal

Build a small semantic retrieval service for course materials or technical documentation.

## Required components

1. A document loader for Markdown or PDF-derived text.
2. A chunking strategy with metadata preservation.
3. An embedding model or embedding API.
4. A vector index or vector database.
5. A keyword baseline such as BM25.
6. A hybrid retrieval method.
7. A reranking step, optional but recommended.
8. An evaluation set with at least 20 queries.
9. A report comparing retrieval strategies.

## Suggested experiment matrix

| Experiment | Retriever | Reranker | Expected lesson |
|---|---|---|---|
| A | BM25 only | none | lexical baseline |
| B | dense only | none | semantic retrieval baseline |
| C | BM25 + dense | none | hybrid improvement |
| D | BM25 + dense | cross-encoder or LLM reranker | precision improvement |
| E | dense with different chunk sizes | none | chunking effect |
| F | dense with contextualized chunks | none or reranker | context preservation effect |

## Report questions

1. Which retriever had the best recall@5?
2. Which retriever had the best nDCG@10?
3. Which queries failed under dense-only retrieval?
4. Which queries failed under BM25-only retrieval?
5. How did chunk size affect results?
6. Did reranking improve answer-bearing precision?
7. What was the latency/cost tradeoff?
8. What would you change before using this in production?
